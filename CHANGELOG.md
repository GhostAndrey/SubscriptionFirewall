## [Unreleased]

### Added

- `GET /readyz` — readiness-проба с проверкой доступности БД (503, если БД недоступна).
- `GET /version` — версия, commit и дата сборки; метрика `subscription_firewall_build_info`.
- `HEALTHCHECK` в Dockerfile и docker-compose через подкоманду `firewall healthcheck`.
- Request-id: middleware `X-Request-Id` (генерация или проброс входящего), request_id в логах запросов и echoed в ответах.
- OpenAPI-спецификация API: `api/openapi.yaml`.
- MySQL в docker-compose с healthcheck; стек поднимается одной командой `docker compose up`.
- Интеграционные тесты MySQL-адаптера в CI (сервис mysql в workflow).
- Публикация Docker-образа в GHCR (`.github/workflows/release.yml`), Dependabot.
- Env-конфигурация: уровня логов (`SUBSCRIPTION_FIREWALL_LOG_LEVEL`), пула БД (`SUBSCRIPTION_FIREWALL_DB_MAX_OPEN_CONNS`, `_MAX_IDLE_CONNS`, `_CONN_MAX_LIFETIME`), таймаутов HTTP (`SUBSCRIPTION_FIREWALL_READ_TIMEOUT`, `_WRITE_TIMEOUT`, `_SHUTDOWN_TIMEOUT`).
- `SUBSCRIPTION_FIREWALL_STORAGE=auto|memory|mysql` — явный выбор хранилища (по умолчанию auto: mysql при заданном DSN, иначе memory).
- `.env.example`, `LICENSE`, этот CHANGELOG; цели `test-race` и `cover` в Makefile.
- OpenTelemetry-трейсинг: HTTP-спаны и спаны детекции, экспорт OTLP/HTTP (`SUBSCRIPTION_FIREWALL_OTLP_ENDPOINT`); Jaeger в compose под профилем `tracing`.
- Redis rate limit: при заданном `SUBSCRIPTION_FIREWALL_REDIS_ADDR` лимит по IP общий для всех реплик; Redis в compose.
- Схема БД переведена на версионированные goose-миграции (`internal/adapter/mysql/migrations/*.sql`) вместо `CREATE TABLE IF NOT EXISTS` в коде.
- Обвязка эмиттера карт: timeout, retry с backoff и circuit breaker (`SUBSCRIPTION_FIREWALL_ISSUER_*`).
- Идемпотентный выпуск карт: бронь в состоянии `Issuing` с ключом `issue:<user>:<merchant>`, восстановление брошенных броней по `SUBSCRIPTION_FIREWALL_ISSUANCE_TIMEOUT`, стабильный `IdempotencyKey` в `ports.IssueRequest`.
- `internal/lifecycle` — единая точка переходов для пары «подписка + карта»: компенсация обратимых действий и отложенная синхронизация необратимых через `lifecycle_sync_outbox` с фоновым сикером.
- Переход подписки в `Zombie` на sweep замораживает связанную карту.
- Метрики `subscriptions_swept_total{state}`, `lifecycle_sync_total{entity,action,result}`, `linked_action_failures_total{entity,action}`, `lifecycle_queue_depth`.
- Валидация инжеста по ограничениям схемы: длины `id`/`user_id`/`merchant_id`/`merchant_name` и границы `authorized_at` (не дальше суток вперёд, не старше двух лет) — `400` вместо `500` от СУБД.
- Оптимистичная блокировка подписок: колонка `version`, `UPDATE … WHERE id = ? AND version = ?` и атомарное создание через `CreateIfAbsent`.
- `docs/CONTRIBUTING.md` — как собрать, протестировать и расширять сервис.
- Индекс `idx_subscriptions_sweep` (миграция `00007`) и порт `ListPendingZombieTransition`: sweep читает только подписки, способные перейти в зомби, батчами вместо полного `ListAll` каждую минуту.
- Предфильтрация кандидатов для детектора: `GROUP BY merchant_id HAVING COUNT(*) >= 2` в базе плюс точечная загрузка истории только этих мерчантов.
- Тест списания лимита через несколько независимых пулов соединений — эмуляция нескольких реплик.
- `SUBSCRIPTION_FIREWALL_ISSUER` — явный выбор эмитента карт вместо жёстко вшитой заглушки; сборка провайдера вынесена в `buildCardIssuer`, неизвестное значение останавливает старт, `simulated` пишет предупреждение о непригодности для продакшена.
- Тесты `cmd/firewall` (парсинг конфига, `addressPort`, сборка эмитента) и `internal/obs` (санитизация логов, метрики).
- Тесты отката миграций по `information_schema` и сохранности данных при пересоздании колонок.
- Тест списания лимита через несколько независимых пулов соединений — эмуляция нескольких реплик.
- Пагинация перенесена в SQL: `ListByUserPage` с `LIMIT/OFFSET` вместо загрузки всей коллекции и нарезки в памяти.
- Расширен набор линтеров: `bodyclose`, `rowserrcheck`, `sqlclosecheck`, `noctx`, `contextcheck`, `durationcheck`, `makezero`, `mirror`, `prealloc`; тесты исключены из проверок контекста и закрытия body.
- Тесты правил домена (жизненный цикл подписки, выдача карты) и репозиториев `memory`.
- Оптимистичная блокировка виртуальных карт: миграция `00008` с колонкой `version`, `UpdateVersion` в порту и обоих адаптерах. `Freeze`/`Reactivate`/`Terminate` больше не затирают списание, прошедшее между чтением и записью.
- `internal/worker` — общий цикл «claim → обработать → подтвердить» для детекционного пайплайна и сикера жизненного цикла, с общим retry и остановкой.
- `pipeline.New` и `lifecycle.NewSyncer` принимают срок хранения завершённых задач; `worker.Options` получил `OnPanic` для парковки упавшей с паникой задачи.
- `SUBSCRIPTION_FIREWALL_IDLE_TIMEOUT` и `ReadHeaderTimeout` на HTTP-сервере: keep-alive соединения и медленные заголовки больше не держат соединение бесконечно.
- Тесты на гонки: списание, попавшее внутрь перехода, потерю бюджета при `Freeze`/`Terminate`, `ErrIssuanceLost`, полный батч в lifecycle-очереди, параллельные `Charge` и `Freeze`.
- `SUBSCRIPTION_FIREWALL_OUTBOX_RETENTION` (по умолчанию `168h`) — maintenance-циклы удаляют завершённые (`done`/`failed`) задачи `detection_outbox` и `lifecycle_sync_outbox` батчами по 1000 строк; memory-очередь lifecycle тоже чистит завершённые задачи.
- Метрики `subscription_firewall_worker_panics_total{name}` и `subscription_firewall_audit_write_failures_total`.
- Детектор требует регулярности интервалов: каждое расстояние между соседними списаниями в пределах ±50% от медианы, а неподписочным MCC нужен минимальный интервал (3 дня по умолчанию) — ежедневные покупки и редкие всплески больше не дают ложных подписок. Медиана чётного числа интервалов усредняет два средних значения вместо выбора большего.
- `SUBSCRIPTION_FIREWALL_TRUSTED_PROXIES` — CIDR-список доверенных обратных прокси: для их запросов IP клиента берётся из `X-Forwarded-For` (крайний правый недоверенный адрес), остальные считаются по адресу соединения. Без списка поведение прежнее.
- `SUBSCRIPTION_FIREWALL_TRANSACTION_RETENTION` (по умолчанию 2 года) и `SUBSCRIPTION_FIREWALL_AUDIT_RETENTION` (год; оба — `0` отключает): проход sweep-а батчами по 1000 строк чистит `transactions` и `audit_log`; миграция `00009` добавляет индексы под выборку устаревших строк.

### Fixed

- Claim lifecycle-очереди MySQL возвращался на середине result set, не закрывая его: следующий `UPDATE` на том же соединении отклонялся с `commands out of sync`. Симптом проявлялся всегда, когда в очереди было не меньше батча, то есть именно тогда, когда сикер был нужен.
- `CompleteTokenIssuance` не проверял `RowsAffected`: перехваченная другой репликой бронь приводила к тому, что карта возвращалась как успешно выданная. Добавлена ошибка `ports.ErrIssuanceLost`.
- `ChangeToken` обращался к `linked.ID` при ошибке поиска counterpart, отличной от `ErrNotFound`, — паника вместо ответа. Обратимые действия теперь откатываются, необратимые ставятся в очередь.
- Переходы жизненного цикла карты делали read-modify-write без проверки версии и писали `spent_in_period` из устаревшего чтения, затирая параллельное списание.
- `keyedMutex` в сервисе карт никогда не удалял записи: по одному мьютексу на каждую пару user|merchant за весь процесс.
- Sweep зависал в бесконечном цикле: при исчерпании попыток по версии строка оставалась в выборке, а SQL-условие (`<=`) было шире доменного (`>`), поэтому строки на точной границе окна никогда не меняли состояние.
- Прерванный sweep терял уже сохранённые переходы: `changed` возвращался, но игнорировался, и подписки-zombie оставались с активной картой навсегда.
- Redis-клиент закрывался до `http.Shutdown`, из-за чего запросы в полете получали `503 rate limiter unavailable` при остановке.
- Горутина sweep не дожидалась завершения перед закрытием БД.
- Детектор применял порог повторов по MCC первой транзакции, а классификацию — по MCC последней; группы мерчантов больше не полагаются на порядок строк из хранилища.
- `memory.ListByUserAndMerchants` при пустом списке мерчантов возвращал всю историю пользователя вместо пустого результата — расхождение с SQL-адаптером, грозившее лишней загрузкой в детекторе.
- `memory.EnqueueWithTransaction` игнорировал переданный контекст и писал транзакцию через `context.Background()`, поэтому отменённый запрос всё равно доходил до хранилища.
- Ручные `rows.Close()` в очередях MySQL-адаптера заменены на `defer`.
- Healthcheck контейнера выполняет запрос с явным таймаутом и контекстом.
- `POST /v1/tokens/{id}/authorize` больше не принимает `amount_minor <= 0`: отрицательная сумма уменьшала счётчик расходов и обходила месячный лимит. Проверка продублирована в домене (`domain.ErrInvalidAmount`), в ответе — `400`.
- Списание лимита выполняется атомарно (`SELECT … FOR UPDATE` в одной транзакции), поэтому одновременные авторизации с разных реплик не могут превысить месячный лимит.
- Две реплики больше не выпускают две карты на пару (user, merchant) и не создают две подписки.
- Блокировка sweep-а берётся и освобождается на одном соединении пула и отпускается при отменённом контексте — раньше `GET_LOCK`/`RELEASE_LOCK` могли попасть на разные соединения.
- Сервис без API-ключей не поднимается: `httpapi.NewServer` возвращает ошибку вместо тихого открытия эндпоинтов.
- `envBool` больше не глотает опечатки: неверное значение в `SUBSCRIPTION_FIREWALL_ALLOW_NO_AUTH` или `_OTLP_INSECURE` теперь останавливает старт.
- `addressPort` проверяет, что порт числовой и в диапазоне: нечитаемый `SUBSCRIPTION_FIREWALL_ADDRESS` больше не превращает healthcheck в невалидный URL.
- `SUBSCRIPTION_FIREWALL_RATE_BURST` применяется и при Redis-лимитере, который раньше его игнорировал.
- Redis-лимитер отдаёт `503` на `POST /v1/tokens/{id}/authorize` при недоступности Redis вместо fail-open на денежном эндпоинте.
- Тело запроса разбирается до конца: JSON после первого объекта даёт `400`, а не игнорируется.
- Статус ответа пишется один раз (первый `WriteHeader`), при панике в лог и метрики попадает `500`, а не `0`; `statusRecorder` пробрасывает `Flush`, `Hijack` и `Unwrap` вместо двойной обёртки.
- Сравнение API-ключей идёт по SHA-256 в постоянном времени и больше не выдаёт длину ключа через `ConstantTimeCompare`.
- `subscriptions_detected_total{state="Zombie"}` больше не растёт от sweep-а — переходы вынесены в `subscriptions_swept_total`.
- `UpdateVersion` подписки различает отсутствующую строку и конфликт версии: раньше оба случая выглядели как `ErrVersionConflict`, и удалённая подписка выдавала себя за retry-ошибку.
- `Save` подписки и карты больше не может молча переписать чужую строку: апсерт по уникальному ключу `(user_id, merchant_id)` возвращает `ErrAlreadyExists`, если запись поглотилась существующей строкой с другим id.
- Добавлены `mysql.Rollback` и `mysql.MigrationVersion` плюс тесты идемпотентности, отката и сохранности данных при миграциях.
- `CompleteTokenIssuance` в MySQL-адаптере поднимал `version` только в памяти: возвращённая карта расходилась с сохранённой строкой, и следующая запись падала с `ErrVersionConflict`. Версия поднимается в том же `UPDATE`.
- `internal/lifecycle` писал запись в `audit_log` до применения парного перехода, поэтому откатанная попытка оставляла след в аудите. Аудит пишется только для окончательно применённого перехода, а доигранные сикером переходы теперь тоже попадают в аудит.
- Sweep выполнял первый проход только через полный `SUBSCRIPTION_FIREWALL_SWEEP_INTERVAL`, поэтому после рестарта просроченные подписки оставались активными до истечения интервала. Первый проход идёт сразу при старте.
- In-memory очередь детекции теряла упавшие задачи: `Fail` ничего не делал. Задача переигрывается в процессе до 8 попыток, затем паркуется с предупреждением — как в MySQL-адаптере.
- Санитизация логов маскировала чувствительные атрибуты только на верхнем уровне: вложенные в `slog.Group` оставались в открытом виде.
- `masking.PAN` не скрывал ни одной цифры, если их не больше, чем видимый префикс и суффикс: короткий PAN теперь маскируется целиком.
- Приватный путь вне `/v1` не требовал скоупа и проходил с любым валидным ключом. `requiredScope` по умолчанию требует `manage`.
- Публичные пути с завершающим слэшем (`/healthz/`, `/metrics/`) считались приватными в auth, но публичными в rate limit и трейсинге. Все слои используют одну проверку публичного пути.
- `SUBSCRIPTION_FIREWALL_RATE_LIMIT` с дробным значением при заданном Redis молча выключал лимитер: `int()` усекал значение до нуля. Теперь такой старт останавливается с ошибкой.
- Заморозка или завершение карты во время выпуска теряли уже созданную у провайдера карту: `CompleteTokenIssuance` отказывался записывать PAN в состоянии `Frozen`/`Terminated`, а `Freeze` на брони падал с `ErrInvalidTransition`. Карта теперь записывается всегда, а состояние, выставленное оператором, сохраняется — токен не «оживает» в `Active`. Бронь, оставшаяся без карты, освобождается в любом состоянии, так что пустой карты в базе не остаётся.
- Sweep при ошибке прохода (не при отмене) выбрасывал уже сохранённые переходы в `Zombie`: подписки были переведены в зомби, но их карты оставались активными навсегда, и зомби мог авторизовывать списания. `changed` теперь обрабатывается и на ветке ошибки.
- Паника в фоновом воркере (детекция, lifecycle-синкер, maintenance-циклы) роняла весь процесс: горутины не имели recovery. Паника логируется со стеком, считается в `worker_panics_total`, а задача помечается `Fail` и уходит в повтор.
- На остановке контекст обработки задачи гас вместе с claim-контекстом: терминальные `Complete`/`Fail` выполнялись с отменённым контекстом и падали, задачи оставались в `processing` до `RequeueStale` через 5 минут. Claim и обработка живут на раздельных контекстах: обработка доживает до терминальной записи.
- Метрики и логи HTTP приписывали все авторизованные запросы маршруту `unmatched`: auth пересоздавал запрос через `r.WithContext`, и ServeMux проставлял `Pattern` уже копии, не видимой observation-мидлварью. Маршрут снимается с запроса, который дошёл до mux.
- Redis rate limiter отсекал по `burst`, а не по `SUBSCRIPTION_FIREWALL_RATE_LIMIT`: устойчивая пропускная способность равнялась burst (по умолчанию 200 при лимите 100), и два режима лимитера расходились на одном конфиге. Отсечение теперь по лимиту; `burst` остался параметром in-memory лимитера.
- Карта лимитеров in-memory не имела жёсткого капа: при более чем 65536 активных IP за 10 минут она росла без ограничений, а каждый запрос платил полный обход карты под мьютексом. Теперь при переполнении вытесняются старейшие бакеты.
- Провал записи аудита после применённого перехода проходил только warn-логом и был невидим для мониторинга: счётчик `audit_write_failures_total` делает потерю аудита алармируемой.
- Graceful shutdown мог висеть бесконечно: фоновый drain (`application.close()`) не был ограничен таймаутом, и зависший SQL-вызов останавливал выход из процесса. Drain ограничен `SUBSCRIPTION_FIREWALL_SHUTDOWN_TIMEOUT`.
- Миграции при старте гонялись без блокировки: две реплики, стартующие одновременно, конкурировали за один `ALTER TABLE`, и проигравший падал с дубликатом колонки в crashloop. `Migrate` работает под advisory-блокировкой MySQL `GET_LOCK` с ожиданием до 30 секунд.
- Задача outbox-а, зависшая в `processing` с исчерпанными попытками (воркер умер на восьмой), навсегда оставалась `pending` с `attempts = max`: claim её уже не брал, а `Fail` не приходил никогда. `RequeueStale` теперь помечает такие строки `failed`.
- `Complete`/`Fail` outbox-ов не проверяли состояние строки: воркер, чей lease истёк, мог перезаписать свежий claim другого воркера — поднять `done` обратно в `failed` или отменить чужую обработку. `Complete` действует только по `status = 'processing'`, `Fail` — только по совпадению `attempts` своего claim-а.
- `Authorization: Bearer <key>` парсился чувствительно к регистру схемы и без обрезки пробелов: `bearer <key>` и `Bearer  <key>` по RFC валидны, но получали `401`. Схема распознаётся в любом регистре, токен нормализуется.
- `masking.Token` для значений длиной 8–12 символов раскрывал почти весь или весь секрет (`abcd…efgh` при 8 символах — это полный ключ с разделителем): API-ключи такой длины писались в логи открытым текстом. Всё маскируется до 12 символов включительно.
- Детектор классифицировал медианный интервал 32–180 дней как `WindowYearly`: квартальная подписка получала годовое окно, и зомби-детекция откладывалась на два года. Годовое окно назначается при интервале от полугода; квартальные списания под окно не подходят и не детектируются.

### Changed

- Трейсинг экспортируется по TLS по умолчанию: `SUBSCRIPTION_FIREWALL_OTLP_INSECURE` теперь `false`, plaintext — явный opt-in для локального коллектора. Раньше спаны с `user_id` уходили по HTTP без шифрования, если не переопределить переменную.
- Лицензия изменена с MIT на Apache-2.0 (текст в `LICENSE`, упоминания в README и `api/openapi.yaml`).
- Репозиторий переведён в приватный режим.
- Репозиторий снова открыт как публичный; у проекта появились описание на GitHub, topics-теги и обновлённое вступление README.
- `cmd/firewall` разбит на `config.go`, `storage.go`, `app.go`, `sweeper.go` и `healthcheck.go`; чтение переменных окружения сведено к единому списку проверок.
- MySQL-адаптер разбит по репозиториям (`transaction.go`, `subscription.go`, `token.go`) и общие хелперы вынесены в `db.go`; SQL-константы и списки аргументов переиспользуются.
- `pipeline` и `lifecycle.Syncer` используют общий `internal/worker` вместо двух почти одинаковых циклов с собственными константами и `sleepContext`.
- Дублирующиеся пути аудита и отката в `internal/lifecycle` сведены к одному `changeable`-интерфейсу.
- `memory`-адаптеры сортируют через `slices` вместо ручных сортировок вставками.
- HTTP-сервер больше не хранит неиспользуемый репозиторий транзакций, а проверка уникальности инжеста перенесена в очередь, которая и так владеет вставкой.
- API-ключ с пустым ключом или пустым списком скоупов (`:скоупы`, `ключ:`) останавливает старт с ошибкой, а не отбрасывается молча, из-за чего часть настроенных ключей пропадала незаметно.
